## 保留的机制

诊断后安排学习路径；按子技能维护 0–5 级；逐题等待学习者；使用预测、解释、纠错、反例和迁移题；基于多次表现而非自评升级；穿插复习；结尾检查技能连接；可保存与恢复状态。

## 有意调整的规则

| 上游做法 | 本地适配与理由 |
|---|---|
| 4–10 子技能、3–5 诊断题，诊断前不教 | 不设固定数量；发现缺前置知识及时给最小解释，避免把诊断变成受挫门槛 |
| 错 2–3 次才直接讲解 | 按错误类型与求助信号选择提示或讲解，保留实际尝试但不拖延帮助 |
| 每次升降级画条形图和总体百分比 | 重要变化或查询时显示技能与证据；增加“未评估”，不制造校准程度未知的总体分数 |
| 偶尔质疑正确回答 | 用真实反例和边界检验，不为扮演反方编造错误前提 |
| 复习失败就降级 | 先区分疏漏、遗忘与概念缺口，范围与证据相称 |
| 所有子技能到目标才结束课程 | 保留目标检查，但用户可结束、改目标或索取直接答案；短练习不强加完整课程 |
| 保存等级和覆盖情况 | 另保留提示、表现、未检查点与当前题，避免把有帮助的答对当成独立掌握；恢复不把历史等级当新证据 |

与 `writing` 的分工：普通清晰解释、文章交付和少量理解桥梁仍由原任务承担；只有系统教学、持续测验或练到独立完成才进入本 Skill。没有新增全局教学门槛，也不为用户未请求的任务自动打分。
