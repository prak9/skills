# 编辑强度与保真边界

先从用户的动词判断允许改到哪里。明确的限制优先于默认值；同一句中出现多档要求时，以用户明确允许的最大改动为上限，同时保留更窄的保护条件。

| 档位 | 常见触发措辞 | 允许的主要改动 | 必须保护 |
|---|---|---|---|
| Proofread / 校对 | “校对”“只改错别字”“修标点”“纠正确定语病” | 错字、标点、拼写、确定的语法错误 | 信息、结构、段落、语气与用词偏好 |
| Polish / 润色 | “润色”“更流畅”“更自然”“精简重复” | 句式、衔接、节奏、无信息重复 | 事实、条件、立场、论证顺序、信息顺序与语气强度 |
| Restructure / 重组 | “重组”“调整结构”“重排段落”“强化论证组织” | 段落顺序、标题、层级、论证组织 | 承重命题、证据与结论关系、引文和观点归属 |
| Rewrite / 重写 | “重写”“换一种体裁”“面向某受众改写”“改成演讲稿” | 整体表达、体裁、详略和受众适配 | 已知事实、明确限定、核心立场及不可改动内容 |

“修改一下”“优化文字”没有更多上下文时默认按 Polish，不自行升级到 Restructure 或 Rewrite。摘要是独立任务，不因篇幅缩短而获得改变结论强度的授权。

## 各档位的停止线

- Proofread 不移动句子或段落，不替换只是风格不同但本身正确的表达。若原句逻辑可疑，标注疑点，不静默重写。
- Polish 不改变信息出现顺序，不删承重重复，不把作者鲜明但清楚的口吻统一磨平。
- Restructure 可以移动材料，但移动后必须仍能辨认每条证据支持哪个结论；引文不能脱离原说话者。
- Rewrite 可以重做表达，不可把推断变成事实、试点变成普遍结论、相关变成因果，或补入未提供的案例与数据。

## 交付前的语义保真检查

先查语义，再查文风。逐项对照原文和成品：

1. 主体：谁做了什么，代词和受影响对象是否相同；
2. 数字：数值、单位、币种、期间、分母和比较基准；
3. 否定：`不`、`未`、`没有`、`不得` 等词作用于谁；
4. 条件：`若`、`只有`、`除非`、例外和适用范围；
5. 因果强度：相关、提示、支持、导致、证实、证明不可擅自升级；
6. 可能性：可能、预计、初步、约等不确定性不得消失；
7. 来源归属：报告事实、作者判断、引文、管理层说法仍归属于原来源；
8. 鲜明语气：讽刺、克制、愤怒、亲密或技术性声音是否仍在。

存在数字、否定、条件、可能性、因果或来源归属的高风险编辑与翻译，可运行：

```bash
python scripts/check_semantic_fidelity.py \
  --source '试点结果提示可能改善。' \
  --revision '试点结果已证明有效。'
```

必要时用多个 `--protected-term` 明确保护主体、来源、术语或短语。脚本只暴露表面标记变化；`pass` 不能证明语义等价，仍需检查指代、论证顺序和跨句关系。
