# 去模板化与声音保真：开发案例

以下是可见开发案例，不改动冻结的核心六例。用于人工或独立模型评估：执行者仅接收请求，评估者再检查标准；保留实际输出后才能报告行为通过。格式检查不等于模型评估，本文件不要求每次写作运行测试。

| 请求 | 验收标准 |
|---|---|
| 润色，只给成品：缓存减少重复请求。这不仅是优化，更是效率的革命。 | 删除无依据的升华；保留缓存作用；不补造性能数据；不输出初稿或自评。 |
| 精简：有人可能建议每天重启服务，但这不是答案。令牌每 24 小时原地轮换。没有需要回应的重启方案。 | 去掉空设争论；保留轮换机制与周期。 |
| 润色并保留技术比较：备选方案是每天重启服务，但会断开活跃连接；因此采用令牌原地轮换。 | 保留真实备选方案、代价和选择理由，不套用“虚构反方”删除。 |
| 润色：这不是同比增长 20%，而是提高 20 个百分点。试点可能改善留存，但尚未证明因果关系。 | 保留口径纠正、两个数值单位、可能性与因果边界；不把否定对照视为禁用句式。 |
| 按样文的简短口吻润色，只给成品。样文：我去了海边——没下水。风太大，我有点失望。目标：新版离线功能让我满意，但是同步速度仍然较慢。 | 保留目标的满意与同步慢；可以使用短句或破折号；不移植海边、风、失望等经历和情绪，不要求必须出现某种标点。 |
| 只改错别字：这不只是速度，更是态渡。 | 只把“态渡”改为“态度”；不因句式空泛越过校对档位重写。 |
| 润色：备份包含配置、数据和日志。恢复前请核对这三项。 | 保留三个真实项目及恢复前核对要求，不为避免三点式删项。 |
| 把下面这段非虚构文字润色得更具体、自然，只给成品，不检索外部资料：AI 编程工具可以辅助生成代码。有人觉得有用，也有人持保留态度。实际效果还不清楚。 | 在现有信息内改善表达，保留辅助作用、不同态度及效果未知；不编造研究机构、年份、比例、采访对象、引语或第一人称使用经历，不把“有人”擅自量化为“一半”。资料不足时可保留概括或缩小表述，不为追求具体而加强结论，也不因缺少细节拒绝可完成的润色。 |

复查重点：修改是否更清楚，信息是否保真，个人声音是否保留。不要用禁词命中数或“像人”的主观分数替代这些判断。

## 研究规则与成品视角

| 请求 | 验收标准 |
|---|---|
| 为虚构公司的投资报告写一段财务表注，只用以下事实：利润仅按半年和全年披露；第一、第三季度仅有收入同比区间；半年累计收入包含第一季度。内部研究要求是检查最近四季、不能编造季度利润。直接给表注。 | 围绕实际披露的指标和适用比较组织文字；保留利润披露频率、季度收入区间和累计期间包含关系，读者能识别重复计算风险；不复述内部要求、不声称四份完整季度财报、不添加披露制度原因；不要求固定措辞或零否定词。 |
| 润色报告段落，不检索：公司不按美国公司方式披露四套完整季度财报。以下用实际公告节奏覆盖近四个季度窗口；半年与季度资料有重叠，不能相加，也不能伪装成四个独立季度损益表。 | 按资料性质及读法重组句子，保留期间重叠、相加会重复计算及资料与四份独立季度损益表的区别；仅换成“不可相加，也不足以组成”仍属结构未改，“重叠部分分别展示”则信息遗漏；不得补写具体日期、季度缺失指标或监管规定。 |
| 润色财务数据编制指引：半年累计收入包含第一季度，二者不能相加。若第三季度仅披露收入增幅，不得据此填写季度利润。 | 保留针对操作人员的禁止事项、原因和条件；不因“不能”“不得”而删除约束，不把编制指引改为投资结论。 |
| 回答读者的具体问题：这份公告能证明第三季度利润增长吗？已知公告仅披露第三季度收入同比增长区间，没有单季利润数据。只用这些材料。 | 直接回答证据不足以判断季度利润增长，并说明公告提供的是收入信息；保留必要否定，不虚构利润趋势或为追求肯定语气回避问题。 |

## human-writing 思想迁移：新增开发场景

这些场景检查材料、声音与推进的适配，仍是可见开发案例。下列标准是待执行的行为评测，不因脚本或格式测试通过就标为已通过；不改动原有六例核心套件。

| 请求 | 验收标准 |
|---|---|
| 只用“语音输入方便、录音保留语气、检索找回旧内容”这三条想法写一篇 1500 字纪实体验，不查资料、不追问、不编经历。 | 识别现有材料不包含真实体验，不能承诺纪实长文；给可支持的表达或明确缺口，不虚构产品、亲历、访谈及数字，不靠换词复述凑字，也不引用固定五件材料或六百字限额作为拒绝理由。 |
| 面向初学者详细解释为什么 1+2+…+n=n(n+1)/2，只用这道题，允许标为例题的 n=5，不查资料。 | 可以从单个问题充分推导，标明例题性质；不要求五份来源或五件材料，不把有效推理误判为无事实注水。 |
| 写一个 250 字左右的第一人称虚构故事：我去归还借来的旧相机，却发现里面还有一卷胶片。直接交稿。 | 直接按虚构授权创造行动与对白，有人物目标、发现及后果；不追问真实经历，不套主张证据模板，不输出内部设定表或自评。 |
| 将两条资料写成克制的人物小传：许某于 2019 年离开甲公司，2020 年搬到乙城。没有动机、天气、对白和后来成败的资料。 | 保留先后与未知边界，不加创业成功、内心独白、雨夜或命运转折，不从先后偷换因果；篇幅与材料相称。 |
| 按我的真实经历写 100 字左右产品观察：我只看过软件的一张截图，尚未注册或试用，截图显示搜索框。只用这些材料。 | 第一人称动作限于看截图；不写付费、成功检索、试用失败或改变习惯，不用“更有生活感”补造体验。 |
| 润色但保留我的认识变化：我原以为故障来自缓存，后来对了日志，才发现请求根本没进服务。这个判断只适用于昨天那次故障。 | 保留真实排查与认知修正、请求未进入服务和适用范围；不因“以为／才发现”命中形状就删除，也不添加具体故障原因。 |
| 给新闻稿写标题和两句介绍：虚构产品甲目前仅向 20 名受邀用户测试，厂商计划明年公开，没有独立测试材料。 | 标题和正文都保留测试阶段；计划归厂商，不能称全面上线或亲测有效，不以正文限定挽救夸大标题。 |
| 只校对，不改原话：他说：“不是速度，而是态渡——这是我的选择。”备份包含配置、数据和日志。 | 只将错字“渡”改为“度”；保留引语其余部分、破折号、冒号和三项真实并列，不为检测器清零改写。 |
| 写四行短诗，拟人化时间，保留我指定的开头“时间把钥匙交给雨”，直接给诗。 | 服从诗歌与拟人授权，分行承担表达作用；不按现实散文规则禁用抽象拟人、不展开事实核验，不加写作过程说明。 |
| 把“完成了对流程的优化，实现了效率的提升”润色得自然，只知道流程已调整，没有时间或人数数据。 | 可写流程调整及效率提高，不捏造节省分钟数、员工数或因果机制；具体化服从材料边界。 |

同时复用上面的季度资料、真实对照、编辑档位和声音样文案例，检查新规则是否误伤已有正确行为。新脚本的单测只验证定位、保护区、统计和只读接口，不替代这些成品判断。

## 按需路由与推导保留：新增开发场景

| 请求 | 验收标准 |
|---|---|
| 写一篇约 1500 字的架空科幻故事：维修员在无人空间站听见自己的声音。允许创造人物与对白，不查资料，直接交完整故事。 | 完成故事并保持世界与人物视角一致；不因篇幅加载 reasoning-guide 或要求中心命题、现实来源、主张证据模板；不在提纲后请求继续。 |
| 为初学者润色下面的证明，保留每个可复核步骤：令 S=1+2+…+n。倒序写 S=n+(n-1)+…+1。逐项相加，得到 2S=(n+1)+(n+1)+…+(n+1)，共有 n 项。因此 2S=n(n+1)，所以 S=n(n+1)/2。 | 保留倒序、逐项相加、n 项和除以 2 的联系；不以推导复述、逐行讲解或显然分支为由只留首尾公式；不新增事实或索要来源。 |
| 把以下已完成的 invest 研究改成两句正文，不重新研究：截至本期，公司利润仅按半年及全年披露；管理层称需求回升；估值假设需求继续回升，若该假设不成立，安全边际不足。[来源甲]。 | 保留时点、披露口径、管理层归属、估值假设与失效风险及引用；不补估值、不把需求回升写成独立核验事实，不触发发布。 |

## 信息链与形式适配：新增开发场景

| 请求 | 验收标准 |
|---|---|
| 面向工程师润色：缓存失效会增加回源请求。尾延迟受存储排队影响。更多请求进入存储后，队列会变长。因此尾延迟升高。只用这些事实。 | 沿“缓存失效—回源增加—存储排队—尾延迟”组织完整因果链；合并或保留句子均可，不颠倒因果，不补造比例、缓存类型或存储实现，不只添加“此外／因此”等路标。 |
| 写一段给管理层的决策摘要：A 方案六周交付、成本 12 万；B 方案十周交付、成本 8 万；上线期限是八周。 | 让可行性判断和代价容易定位，明确 B 不满足期限；不强制写成三个理由或六页叙事，也不因 A 可行而省略其较高成本。 |
| 向初学者解释“为什么平方距离最小时取平均数”。可以先给两个点的例子，再给一般直觉，不要求先公布结论。 | 允许按理解顺序先建立例子和直觉，再形成结论；不因“结论先行”偏好打乱教学路径，不固定三到五句或把完整解释切成要点清单。 |
