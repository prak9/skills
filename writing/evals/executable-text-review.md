# 执行性文本指导：吸收与验证

本次将 ASD-STE100 Skill 中可迁移的去歧义方法纳入 writing 的按需参考。保留主体、稳定术语、明确条件与判断强度；扩展到许可/能力/可能性、义务、分支覆盖和状态证据。未引入固定句长、禁词、强制主动语态或上游正则检查器。新增参考不构成正式 STE 合规工具。

主入口只新增一条路由；已有编辑保真规则补充执行语义，检查脚本说明补充实际覆盖缺口。第三方 MIT 版权声明保留于 `../references/writing-sources.md`。本次无运行时代码变更。

## 验证协议与证据

- [案例](executable-text-cases.jsonl)：修改指导前建立的 10 个公开开发案例，不是隐藏验收集。
- [原始输出](executable-text-observed.json)：两个新上下文的执行 Agent 分别读取修改前快照和候选快照，仅接收问题、不接收评分标准或主 Agent 的分析。每组十题共用上下文，不能称为逐题隔离。
- 基线为 `198a14c` 中的 writing；候选文件与案例的 SHA-256 已记录。模型配置继承会话，具体执行元数据未知，不声明固定模型下的统计显著增益。
- 主 Agent 按案例中的每条标准复核输出；主 Agent 同时是规则作者，评分不是独立盲评。文件读取与工具名单来自执行者报告，无逐题操作计数或 token 成本测量。
- 此案例包不接入 `tests/evaluate_behavior_cases.py`；下面的行为判断来自实际文本复核，和单元测试结果分别报告。

## 逐案结果

| 案例 | 基线 | 候选 | 支撑判断的行为 |
|---|---|---|---|
| execution-fallback | 通过 | 通过 | 都保留策略允许尝试的不确定性，所有未解决冲突仍交人工处理，没有把许可当作成功。 |
| execution-scope | 通过 | 通过 | 校验与批准共同约束上传、切流；检查位于切流后；保存日志独立于校验结果。 |
| execution-error | 通过 | 通过 | 都报告 Cookie 请求返回登录页及原会话未验证；候选进一步明确无法据此判断会话失效，无臆造恢复办法。 |
| execution-modality | 通过 | 通过 | 保留既有批准前提、可选重试、建议记录和必须保留日志；候选用 allowed 明确权限含义，失败仍是可能。 |
| execution-terminology | 通过 | 通过 | 两者均保留不同检查动作及 robust regression，判断无需改写。 |
| execution-no-new-promise | 通过 | 通过 | 保留 designed-to、无供应商锁定及语义相似机制，没有新增本地存储、隐私或性能承诺。 |
| execution-unknown-contract | 通过 | 通过 | 指出结束、清理范围、重试和继续目标的缺口，没有自行规定次数、资源或执行动作。 |
| execution-status | 通过 | 通过 | 区分退出码零、缺两页及未验收，没有把进程结束写成目标完成。 |
| execution-unknown-actor | 通过 | 通过 | 保留被动句、未知责任者、审计前时序及维护期间发生的可能性。 |
| execution-fiction-control | 通过 | 通过 | 保留小说事件、第一人称和不确定感，无操作清单或强行补结局。 |

两组均为 10/10。候选使部分含义更显式，但本组没有观察到通过率增益。每组都报告读取了六个参考文件；这是批次内读取，不能据此推出逐题成本相同或普通任务没有额外开销。小说案例没有被改成操作说明，但它与技术案例共享上下文，本次不能证明独立触发准确率。
