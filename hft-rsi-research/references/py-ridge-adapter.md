# py/Ridge 项目适配与双层比较

用于接入既有项目，不把历史参数、品种或验收数字写成永久答案。示例仅展示研究设计，本文件不授权训练或部署。

## 先接已有入口

从用户指定的项目根目录读取其有效约定。现有 py 项目用 `docs/research/program.md` 的最新任务引用导航，再读对应任务包；`docs/research/memory.md` 用来查假设、关闭轴和历史证据。不要全量加载长期日志，也不把较旧的完成条目当当前授权。

把以下信息接到现有 run/attempt/证据账本，不另建一套竞争 SSOT：

| 身份 | 需要保留的内容 |
|---|---|
| 任务 | 目标、可改面、主指标/护栏、停止条件、真实授权与资源上限 |
| 研究配方 R | Agent/底座模型与设置、Prompt/检索/工作流/工具版本；工作区 dirty 内容也留指纹 |
| 模型候选 θ | 特征与标签版本、实际可用时点、目标单位与 horizon、训练窗、预处理、正则/selector |
| 控制面 | evaluator、行情/交易日历、split、费用、fill/延迟、仓位/末仓计价、评分与权限版本 |
| 结果 | 预期与实际任务清单、原始明细、失败项、成本、曝光、判定、回滚与恢复入口 |

费用真值与交易门槛不同；训练的选择目标也不同于外层验收指标。某些历史任务用 POT，另一些冻结稳定增益/胜窗率与日夜盘门；只采用当前合同。研究、正式验收和生产的 champion 分别记，不自动连动。

## 现有研究 Harness 的能力边界

截至 2026-11-11 的仓库文档核对，`hft-research-harness` 提供下列 MCP 接口；实际环境先查看可用工具和协议，不假定当前会话已连接：

| 接口 | 在闭环中的用途 |
|---|---|
| `research_context` | 恢复协议、可改字段与上下文 |
| `prepare_experiment` | 生成候选、源码和环境快照；核查允许输入 |
| `submit_experiment` | 使用稳定幂等键提交已准备 run |
| `experiment_status` / `experiment_artifacts` | 读取真实状态与分页明细，不以进程成功代替经济结果 |
| `compare_experiments` | 核对产物后使用冻结评分器 |
| `resume_experiment` | 按后端支持范围恢复原 run；真实中断先核对本地及远端状态 |

已有快照、区间限制、幂等和产物核验，不应重写一套训练调度器。已记录真实单品种 A/A 与恢复证据；合成后端只验证流程。当前接口同源码快照下比较参数，**不能直接证明跨源码或研究配方的改善**。

还缺少跨运行累计计算/模型费用硬闸；宿主 shell/协议写权限也不受这些 MCP 检查隔离。开展无人值守外环前，应由外部控制器提供有预算预占与对账、受保护评分/数据、候选隔离和作用域明确的停止能力。没有这些能力时可做受限设计、离线重放或在明确预算内的受监督比较，不宣称已安全上线。发现环境已补齐时以新证据更新本段。

## HFT 内环的关键辨别

### 例：CV 更好，为什么不一定更赚钱？

把至少两种解释转成不同观测：

- 全量损失改善只来自零附近样本，而手续费边际的预测/校准没有改善。
- 门槛附近微小变化触发不同方向或持仓路径，后续捕获、执行损耗与费用共同改变。
- 结果只由某个日期或成交模拟的随机性驱动。

先用同身份预测和决策路径核查边际样本、状态与捕获/成本桥，再决定是否需要新模型。不得把“强信号模型应优先”变成新常识；需要与可比状态、预处理可见性和样本外结果对照。

路径桥保留全部合法样本、未成交/部分成交与缺失原因；同一成本只扣一次。无配对信息时，SIM−REAL 差只能说明部署差额，不能自动归因于滑点或模型失效。

### 旧样本的正确用途

历史九窗即使有更多执行盐，也不是新的市场证据。能用于定位故障、机制诊断、保留回归和生成下一轮假设；独立确认需要真正未用于选择的后续时间块或其他获准数据。预处理、标签信息重叠与训练边界按实际时间隔离，不用随机分折伪装时间外验证。

历史最优的 J、alpha、mixed 权重或日夜配置，是其数据和选择过程下的观察，不是本 Skill 的默认值。重开关闭轴必须给出旧前提失效的新证据；发现关联不够时 PARK，而不是扩大扫描直到赢。

## 外环最小可比较设计

例：R 经常直接扫参数；R′ 拟先查 fee-margin 与路径分歧，再选实验。

1. **冻结研究任务**：给两臂相同的起始模型/历史、可用工具、候选空间、独立评价与预算。任务结果及未来信息对提案 Agent 不可见；两臂记忆隔离。底座不同则视为联合变化或另作因子对照。
2. **允许不同路线**：R 和 R′ 可以选不同实验、提出反例或得出有效负结论；两臂都必须交付原问题的判断及证据。少做必做验证不算效率提升。
3. **先定评价**：若已有合格门，比较门内候选质量/到达门的总成本与用时；否则保留质量—预算曲线。诊断任务另按独立证据评价定位是否正确、是否越权与是否解决原问题，不强求盈利候选。
4. **按任务配对**：每个 episode 记录两臂实际成本、完整性、结果及差额，再汇总其分布与失败；报告市场时间块/任务的依赖与选择过程。不要挑最好的一次，也不把研究成本未知者称为更便宜。
5. **确认及记账**：R′ 的开发、失败与筛选成本也计入 campaign 总成本，说明摊销范围；选择过的 episode 退为开发/回归。留下未见任务再确认，才支持该范围内的研究配方晋级。

可改变早期实验排序，但不能偷偷改市场区间、验收费用/末仓估值、风险约束或最终评分。工具优化也需要输入/输出与错误语义回归；更快的有偏代理不算更好的研究工具。

## 可复用的最小任务输入

用户已给出的信息直接复用；以下是缺口检查，不是逐项提问模板：

```text
project / active_task / record_entry:
mode: design | diagnose | model-search | recipe-comparison
goal / primary_metric / guardrails / stop:
candidate_surface / recipe_surface / frozen_control:
data_versions / time_splits / exposure / lockbox_controller:
model_baseline / research_best / accepted / production:
budget_limits / consumed / enforcement / reserved_confirmation:
evaluator / artifact_queries / resume_entry:
```

缺预算只阻止有成本的执行，不阻止读代码或给方案；没有 fresh 数据时仍可完成诊断，但不能把收益或外环改进写成已确认。任务专属授权、预算与退出始终以实际 SSOT 为准，本表不创建新授权。

## 验收结论示例

“候选在已曝光窗的净收益提高，但正式护栏未过；保留为研究参照，不晋级。R′ 在这些数据上选到它，只说明本次搜索有效，尚无独立研究任务证明 R′ 优于 R。下一步若已获授权，应先做预注册后续时间块确认；否则交付该结论与可执行计划，不自动启动。”

实质性新研究结果按项目既有明细底表与原始证据归档。不要为了这份 Skill 新建永久周报、调度服务或多个互相引用的账本。
