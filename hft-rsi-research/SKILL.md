# HFT 研究系统的有界自改进

这里的 RSI 指 Recursive Self-Improvement。目标不是无限调参，而是让系统用可核验的证据改进模型，也改进“如何做研究”。自动找到更高分的模型，只证明候选优化；写了复盘或修改了 Prompt，也不证明研究能力提高。本 Skill 不意味着基础模型权重自我训练。

## 两层对象，两份结论

| 层 | 可改对象 | 要证明什么 |
|---|---|---|
| 模型内环 | 当前项目明确开放的标签、特征、Ridge 训练或选参政策等 surface | 固定评价口径下，候选的成本后经济表现与护栏是否改善 |
| 研究外环 | 版本化研究配方：怎样选实验、诊断失败、检索经验、停止，以及获准修改的工具 | 在新的研究任务上，以可比总预算得到更可靠的判断或更好的已确认候选 |

评价器、封存数据访问、预算权限和生产门禁属于外部控制面，不是自改进对象。模型候选、研究配方和控制面分别版本化；修复判官另立版本并重评两臂，不用新口径挽救旧失败。

## 从当前项目恢复，而不是从历史最优开始

读取项目指定的当前任务、协议、记忆及真实接口，复用既有账本。明确本次是设计、诊断、模型实验还是研究配方实验；恢复可改面、数据曝光、评价命令、当前基线、预算和停止条件。未知授权不从另一任务的余额推断；普通已授权步骤不逐次请示。

接入现有 py/Ridge 项目或研究 Harness 时，读 [项目适配与研究配方比较](references/py-ridge-adapter.md)。只有核算日报或逐笔路径时才转交 `hf-futures-analysis`；不要为每个研究任务强制跑日报。需要额外的消融、预测或 Harness 方法时，按问题选用已有研究参考，不串行执行整套方法库。

## 模型内环：让实验改变判断

- 从一个真实缺口形成竞争解释和可证伪预期。优先做能改变方案排序的最便宜检查，而非直接扩大网格；工具、数据或口径故障先按其性质处理。
- 在允许的 surface 内设计有意义的比较；需要单独归因时隔离变量，有交互时用对应对照。当前 frozen evaluator 决定主指标，MSE、IC 或命中率只作诊断。
- 核查从决策时点可见的特征、标签和预处理，到预测、eligible 信号、仓位路径及成本后结果的传导。硬门槛和已有仓位能放大小预测差；不要从预测线性混合推断利润线性变化。
- 通过项目标准入口执行并核对真实产物、失败单元与配对比较。不同日期、日夜盘、品种及执行随机性的差异按结论需要展开；多次执行盐不等于多个独立市场样本。
- 把选出候选与 fresh 确认分开。重复看过的窗口只能支持已曝光证据；封存数据只能由有权控制器按协议调用。持有宿主 shell 的 Agent 不因一份 manifest 就获得数据隔离。

保留研究最好、正式验收通过和生产在用三种身份。失败不覆盖最好成果；无效输入、作业失败、有效负结果和经济不达标分别记录，不把它们都解释成模型无效。

HFT 的新市场反馈是外生且可能变动的。增加算力、执行盐或合成样本，不能加速未来行情到来，也不能创造真实对手反应、成交和容量证据；研究速度提高不等于可交易优势持续提高。

## 研究外环：改进提出实验的系统

从运行轨迹定位一个可迁移缺口，再提出研究配方 R→R′ 的小改动，例如：先检验成本边际再扩网格、复用经核验的不可变统计量、检索关闭轴的前提及重开证据。不要把“上次 J 最好”写成默认选参规则，也不要仅为变化而自改写。

比较单位是一个完整的**研究任务 episode**：初始信息与可改面 → 选择及执行实验 → 交付判断/候选及证据。冻结两臂的初始信息、允许搜索空间、外部裁判和资源上限，让配方选择不同实验；若强制两臂做同一组实验，就没有测试实验选择能力。

在未参与配方开发的任务或后续时间块上，隔离运行 R 与 R′，封存两臂结果至比较阶段。既有任务重放可检验记忆、恢复和判断，不能冒充 fresh 市场收益或新研究能力；任务材料只提供当时可知的信息，不能泄露未来结论。

按预声明目标比较预算—已确认质量曲线、到达合格结果的时间，或判断正确性与完整性；没有合格候选时保留负结果，不捏造统一分数。计算完整成本：配方开发、提案、数据准备、训练/仿真、失败重试、校验、分析和人工接管。CPU/GPU、费用、墙钟时间与人工时间分别记；未声明换算关系不相加。公平对照也要给 R 相同的资源上限，不能用更强底座或更多试验冒充配方收益。

只有跨预声明任务的独立结果支持、关键回归未破坏且成本值得，才把 R′ 记为该范围内的已验证配方；否则保留 R。一次候选盈利、模型互相赞同或合成后端通过，均不证明递归改进。每轮选择 R′ 本身也计入搜索与数据曝光；比较用完的任务转为开发/回归，不再称未见。

## 状态、边界与交付

沿用项目记录关联：任务/假设、模型及配方版本、协议/数据/代码指纹、run 与 attempt、曝光/预算累计、产物/评分、决定和下一步。记忆保存“观察—解释—适用前提—反证/重开条件”，不是不断堆叠指令。断线先查原 run 与资源归属，再按现有恢复接口续接；未知结果不重复提交，不停止其他任务。

仅在当前授权内继续到目标完成、预算耗尽、证据收敛、用户停止或确需新决定；区分这些终态。不自动扩预算、换评价目标、打开关闭轴、访问封存集、改共享 Skill/权限或替换生产。预算、数据访问与评分权限尽量由工具/执行环境强制；尚无硬闸时明确该缺口，不把文字约定说成已隔离的无人值守系统。

实质性结果先写回项目既有研究记录，保留版本、原始证据、适用前提和反证/重开条件，再推进依赖该结论的实验。已有持久计划时，同步其结论、状态和证据引用，遵循 `plan-skill` 的写回与完成规则；不因一次结果归档另建计划。项目或用户要求长期知识沉淀时，按指定知识库规则提炼可复用结论，链接研究证据，不复制运行账本。完成前核对必要写回已存在，交付时指出位置；只读或不记录要求优先。

最终先给结论，再给足以复核的比较：改了什么、实际观察及计算、支持/排除哪些解释、完整成本与曝光、哪些未知，以及证据位置。分别写清“模型改善是否成立”“研究配方改善是否成立”，以及真实执行范围；设计、合成控制测试、Agent 行为检查和真实市场验证不能互相代替。
