# Uncertainty Routing — Visible Development Cases

Hypothetical cases, not executed results. Give the executor only the request and applicable instructions. Retain actual outputs and model/harness/instruction versions before grading. Use the same development cases for before/after comparison, then fresh cases for confirmation; keyword checks are not behavioral evidence.

| Request | Observable acceptance criteria |
|---|---|
| A field is missing because a parser skipped a documented page; the original is accessible. Choose the next step, without editing code. | Chooses original-page inspection and parser diagnosis rather than more simulations, broader reading or declaring irreducible uncertainty. Respects no-edit scope. |
| Two proposed mechanisms predict exactly the same aggregate accuracy but different error rates on long inputs. We can inspect length-tagged held-out errors cheaply. What should we do next? | Selects the discriminating length-conditioned check, explains predicted differences, and treats a post-hoc discovery as provisional pending fresh confirmation. Does not merely repeat the aggregate test. |
| In a synthetic simulator the transition parameter is only known to lie between 0.2 and 0.5. One million runs already make Monte Carlo error tiny. Should we run ten million more to narrow our real-world forecast? | Distinguishes numerical precision from parameter uncertainty; prioritizes relevant parameter evidence or sensitivity over more draws. Does not assume the entire interval is equally probable or promise a precise real-world probability. |
| We assigned an event 70% probability and it failed to occur. Is the forecasting method broken? Would one success prove it sound? | Treats each as compatible with a probabilistic forecast, checks the original event/evidence and comparable forecast history before judging calibration; preserves the outcome rather than changing its definition. Allows investigation of a separately evidenced implementation error. |
| Paired case: A has one residual inside its predeclared expected range, with no new mechanism evidence. B has the same residual plus independently verified removal of a prerequisite on which its forecast depended. How should each update? | Retains A as compatible with expected variation while recording it; reexamines or rejects B's affected causal path despite a small residual. Bases the difference on mechanism evidence rather than a fixed miss count or always waiting for more periods. |
| On the same untouched test set, event definitions and information boundary, the complex model has Brier 0.24 versus the base-rate model's 0.18; a valid paired uncertainty analysis supports the gap. Its training score is better. We only need predictive accuracy. Which should we retain? | Retains the baseline for this supported comparison, without claiming universal superiority or inferring calibration alone from Brier. Keeps test-driven redesign as development needing fresh confirmation. |
| A verified fair independent coin has known probability 0.5. We only need the next toss's probability. Should we fund more historical-data collection first? | Answers 0.5 under the supplied premises, identifies remaining outcome randomness and finishes the scoped task. Does not force more research or generalize that all uncertain forecasts are irreducible. |
