# 微信公众号正文兼容契约

把本文件作为保守兼容配置，而不是微信官方公开标准。平台过滤行为可能变化；脚本通过只能证明命中了本契约，不能替代真实编辑器粘贴和预览。

## 产物边界

- 干净产物只包含一个顶层 `<section>` 正文片段，不包含 `DOCTYPE`、`html`、`head` 或 `body`。
- 所有视觉样式写在元素的 `style` 属性中，不依赖外部 CSS、字体、JavaScript 或运行时资源。
- 每个非空文本节点都放在 `<span leaf="">` 内。图片本身也放进 leaf span，但不得把图片 URL 变成文本。
- 预览页是独立产物。它可以使用完整网页结构、CSS 和复制脚本，但复制区域内只能放干净正文片段。

## 允许的正文表面

正文只使用：

- 结构：`section`、`p`；
- 行内：`span`、`strong`、`em`、`a`、`br`；
- 媒体：`img`。

属性限制为：

- 通用 `style`；
- `span` 的 `leaf`；
- `a` 的 `href`；
- `img` 的 `src` 与 `alt`。

链接和图片只接受 `http`、`https` 或相对路径。拒绝 `javascript:`、`data:`、事件处理属性和未知协议。

## 禁止项

正文不得包含：

- `style`、`script`、`link`、`iframe`、`form`、`button`、`svg`、`video`、`audio` 或 `div` 标签；
- `class`、`id`、任意 `on*` 事件属性；
- `position: fixed|absolute|sticky`、`float`、`display:grid`、CSS 变量、`@media`、`@keyframes`、`@import`、`expression()` 或 CSS `url()`；
- `white-space:pre` 或 `pre-wrap`。代码块按行输出，用行级段落与可见缩进表达；
- 外部字体文件、远程样式表或依赖浏览器脚本才能出现的内容。

不要用纯正则替换 HTML 来“修复”这些问题。回到渲染源或主题配置，重新生成并验证。

## 内容完整性

- 保留原文每个实质段落、标题、列表项、代码块、链接和图片位置。
- 排版可以重建层级，但不能改变结论、数字、专名、引用归属或语气强度。
- 不自动添加作者身份、品牌背书、二维码、引导关注或互动 CTA。
- 不把普通文本猜成链接，不为没有说明的图片编造说明。
- Markdown 不支持的复杂结构先转换成可核对的简单结构；无法无损转换时明确列出差异。

## 视觉底线

- 正文基准字号至少 16px，行高约 1.75–1.9，单段不过度拥挤。
- 颜色以中性正文承重，主题色只做章节、边线和少量强调；同一段不叠加多种强调。
- 正文与背景对比度至少 4.5:1；自定义主题由渲染脚本检查核心文字组合。
- 图片使用 `max-width:100%;height:auto;display:block;margin:0 auto`，避免把小图强制拉伸。
- 代码按行渲染并允许长行换行；不要用源码缩进制造视觉空白。

## 验证顺序

1. 运行 `scripts/validate_wechat.py`，清零 ERROR。
2. 阅读所有 WARNING，尤其是相对图片路径和需要平台端上传的资源。
3. 打开复制预览，检查 375px 与约 677px 宽度下的换行、溢出、留白和图片。
4. 真正发布前，在微信公众号编辑器粘贴并打开手机预览；这一步才验证平台当前行为。
