# Iterate

在既定目标、预算和权限内持续选择路线、获得反馈并保留最佳已验证成果。首个可用解、一次提升或初始计划完成只是迭代节点；是否继续取决于验收、剩余预算、关键未知和仍可执行路线，不取决于固定轮数。

## 建立迭代契约

复用已经确认的目标、预算、评价标准、范围和必须保持的条件，简短说明评价方式与第一步后开始。预算未指定就不虚构；评价标准缺失时从用户希望得到的结果建立可检查标准，不自定提升百分比。需要比较时先建立可复现基线。

读取当前问题适用的领域 Skill，让它定义正确性、测量和工具；只加载需要的分支。`iterate` 负责探索与收敛，不替代领域判断。自主迭代也不增加提交、推送、部署、交易、外部写入、删除资源或修改评价器的权限。

根据请求选择协作意图，不要求用户填写模式：

- **交付**：验收清晰时，由 Agent 闭合调查、修改、运行、修复和证据整理，人只保留真实的产品或风险决定。
- **共研**：问题定义、机制或架构取舍会随证据变化时，保留人的初始判断和关键路线选择；Agent 提出竞争解释并完整执行区分性实验。
- **学习**：掌握机制本身是目标时，保留预测、解释、反例或迁移检验，不用一份能运行的产物冒充理解形成。

模式可以随任务变化。不要把共研或学习误做成纯委托，也不要让人在交付模式里承担重复运行、搬运报错和常规修复。

## 证据驱动的循环

每轮选择最可能改善成果、排除关键误判或打开后续路线的问题。行动前留下足以检验的预期：为什么现在值得做、预计观察什么、怎样验证、什么结果会改变选择。优先使用便宜且有区分力的观察，但不能靠持续做边缘小实验回避主要瓶颈。

按证据组合这些动作，而非机械依次执行：

- **探索**：比较机制不同的解释、工具或解法；不靠同一参数的轻微变化伪装路线多样性。
- **探针**：用最小、隔离、可恢复的实验快速淘汰弱方向。
- **验证**：复现、测量、构造反例、做对照或消融，区分实现错误、仪器失效和假设被否定。
- **换路**：重查问题定义、测量和瓶颈；保留旧方向的排除依据与重开条件。

结果出来后更新下一选择并继续执行授权内工作，不把仍可完成的实验留成建议。反馈稀疏时，用中间产物或反例缩短周期，同时保留它与最终验收的区别。计算成为瓶颈时，先问哪些工作可以证明不必做，再考虑加速原计算。

把准备、执行、验证、返工和等待计入完整任务成本。成功轨迹不证明每一步有效；需要归因时做有区分力的对照。选题、采样或策略改变时，检查是否只是换了更容易的样本。连续研究按需读取 [研究飞轮](../research-craft/references/research-flywheel.md)、[过程与采样检查](../research-craft/references/harness-engineering.md#evaluate-trajectories-and-policy-generated-data) 或 [消融设计](../research-craft/references/ablation-design.md)；普通改动不建立研究台账。

## 规划、并行与恢复

单个低成本实验直接开展。多个依赖步骤、跨会话恢复或独立任务包使用 [plan-skill](../plan-skill/SKILL.md) 的最轻适用模式；`iterate` 选择下一问题和停止时机，`plan-skill` 保存执行状态。证据改变路线时更新或撤销依赖任务，不为完成旧清单继续失效工作。

只有存在可隔离、可独立验收的工作时才并行。主 Agent 保留目标、总预算、最佳版本和整合责任；委派说明起点、问题、可改范围、预算、产物和验收证据。候选分开写入，验证读取原始产物，组合后重新验收；多个 Agent 的一致意见不是独立证据。

长任务沿用项目已有计划、版本、日志和产物保存当前问题、最佳已验证版本、关键尝试、证据及下一动作，不另建重复状态系统。恢复时先核对实际版本、产物、运行任务和支撑旧结论的前提，再继续。

## 验证与成果保留

候选晋级分别判断：必守条件是否通过、目标表现是否改善、证据是否足以替换当前最佳。沿用同一目标、工作负载和取舍；指标不可比时保留分歧，不临时挑有利口径。用适当的对照、重复测量或独立案例确认优势；噪声、反复选优、因果归因或评价器可信度成为问题时，使用 [research-craft](../research-craft/SKILL.md)。

验收依赖实际运行和产物，不依赖执行者叙述。不得削弱测试、删除失败样本或改变口径制造成功。评价器确有错误时单独修复，并在新协议下重测基线和候选。

经验只在证据支持的最窄范围内保留，记录适用版本/环境、动作、结果、证据和失效条件。区分待验证、已验证和过时；相关前提改变时重评依赖结论。若要宣称经验提升了能力，在干净起点和未用于调整的案例上与适当基线比较，并计入探索与执行成本。

## 阻塞与结束

失败时先定位方法、实现、输入、仪器还是整个目标受阻，并在授权和预算内尝试有依据的修复或替代。局部受阻不停止独立工作。真正无法继续时，说明影响、已做检查、仍缺条件、责任方和恢复动作；不靠降低验收或扩大权限绕过。

持续关注已用与剩余资源，为最终验证和交接留出预算。费用或 token 不能准确计量时标为未知，不编造。停止分为：

- **目标完成**：验收证据和授权内必做交付均完成。
- **搜索收敛**：开放优化中，主要瓶颈和有希望的不同机制已有检查，剩余路线在当前范围与成本下难以改变选择；不宣称全局最优。
- **预算耗尽、用户中止或受阻**：保留最佳已验证成果并如实说明未完成部分，不报告为成功。

结束时停止新实验，安全取消本次可取消工作，记录其他运行任务。交付目标与结束原因、预算使用或未知边界、最佳成果的版本和证据，以及仍会改变结论的未决事项、重开条件和恢复方式；没有的部分省略。
