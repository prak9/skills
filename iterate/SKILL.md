# Iterate

自主选择路线，用证据学习；积累可复用经验，而不是积累轮数。流程是可调整的方法，不是逐项审批清单。探索、诊断和排除错误方向都可以有价值，但不能冒称性能提升或目标完成。

启动后持续执行“选择问题—实际试验—核对结果—更新路线”，而不只在开头引用本 Skill。首个可用解、一次提升、测试变绿或完成初始计划，都不自动意味着探索任务完成；用户要求继续时承接已有目标、证据与未决方向，不重新退回单次建议模式。

## 起点与边界

复用上下文已经确认的目标、预算、评价标准、允许修改范围和必须保持的条件。先简短说明目标、评价方式与第一步，随后检查相关代码、资料、历史尝试和运行状态，尽快获得真实反馈。需要比较时建立基线；不为每个探索性想法强制创建完整计划。

先分清任务要的是满足明确条件，还是在预算内寻找更好的方案。前者按验收结束；后者不能把“有改进”自行当成达标。识别实际适用的领域 Skill 并读取所需部分，让它提供测量口径、工具和验证方法；不要仅列出名称或以通用迭代流程代替领域方法，也不为凑覆盖加载无关 Skill。

- 评价标准未指定时，从用户希望得到的结果建立可检查的标准；不要把宽泛优化请求改成自己编造的提升百分比或成功阈值。
- 范围内的常规可逆工作自行推进。先调查可查缺口；只有无法自行解决、且实质影响目标、授权或验收的用户决定才提问，同时完成不依赖答案的工作。
- 自主迭代不增加提交、推送、部署、实盘、外部写入或删除资源权限；也不授权修改评判自己的标准、权限控制或共享 Skill。

## 方向不清时，先人机共创

当目标含义、价值取舍或候选方向存在实质不确定性，且用户判断能明显改善方向选择时，主动邀请简短的 brainstorming。先利用已有资料，提供对问题的理解、区分事实与假设，并提出机制不同的候选方向及其价值、代价和关键未知；不要空手问“你想怎么做”，也不要把协作变成逐题审问。围绕真正影响选择的分歧交流，允许用户提出新方向，不要求固定数量的选项或逐段批准。

意图与取舍需要共同澄清；可查事实、技术可行性和瓶颈优先自行调查或实验，不让用户替 Agent 做技术诊断。讨论中可以穿插已授权的低成本探针，用结果帮助选择。尚待用户判断的关键取舍不擅自拍板，同时推进不依赖它的工作。

收敛到“知道接下来值得验证什么”即可，不必预先解决所有未知。简短保留共同明确的目标、方向、取舍、边界及待验证假设，沿用已有授权进入规划和执行；方向已明确则跳过，不把 brainstorming 变成通用审批关卡。

## 每轮选择最有价值的问题

在有意义的迭代节点，根据证据判断：成果是否足以交付、下一步最值得消除什么不确定性、经验应怎样改变行动、是否遇到用户保留的决定。这是掌舵责任，不是每轮必须输出的四问表格或审批关卡。目标与授权不随实验漂移，路线、假设和中间里程碑可以调整；原路线被否定时换路线，若证据表明目标在现有约束下不可行，交付依据和具体待决定事项，不偷偷换目标或无限追逐不可能的结果。

行动前简要明确：为何值得尝试、预期观察、验证方式，以及何种结果会否定想法。可以记在现有任务记录中，不要求每轮向用户展示固定模板。

在现有记录中保留有价值但尚未检验的方向，以及已排除方向的证据。每次结果出来后，用它选择并执行下一项，而不是把仍可执行的已授权工作写成“建议下一步”后收尾。探索深度看是否解释关键瓶颈、检验影响结论的替代机制和挑战当前最好方案，不看轮数、角色数或报告长度。

反馈稀疏时，用可检查的中间产物或反例缩短反馈周期；运行时长、调用数量和完成计划步骤本身不是研究进展，中间检查通过也不等于最终验收。

根据证据选择或重排这些动作：

- **广探索**：瓶颈不明时，检查机制不同的解释、工具路径或解法，建立足够完成目标的环境地图；无需遍历所有功能。
- **深验证**：瓶颈已知时，直接复现、测量、构造反例或测试边界；不强制先广后深，也不要求每轮更难。
- **小实验**：先做成本低、可隔离、可恢复的探针，再向有希望的候选投入。实验可以是代码、检索、测量、对照或消融。
- **换路线**：反复低收益时，重查问题定义、测量有效性和瓶颈，尝试新机制，而非无理由微调。同一失败不能靠改写叙述变成新证据；一次失败或固定无进展轮数也不自动结束任务。

局部调整见效后，检查主要瓶颈是否转移、收益是否稳健，以及是否仍有值得验证的不同机制；局部调整失败时，区分方法失败、测量失效和问题定义错误。用能改变选择的实验推进，不机械穷举所有方向，也不为消耗预算重复已无信息增量的操作。

允许大胆探索和多个因素一起变化来发现方向；若要把收益归因于某个因素，再用有区分力的对照验证。经验关系不自动成为因果规律。

探索陌生环境的写操作优先使用副本、测试账号或可恢复状态；不要把真实用户数据、生产系统当作试错场。已有授权不清楚是否覆盖某个副作用时，先做不产生该副作用的检查。

## 从方向到具体任务

选定方向后，若需要多个相互依赖的步骤、跨会话执行或多个 Agent 协作，使用 [plan-skill](../plan-skill/SKILL.md) 将方向转成具体任务，明确产物、依赖和验收证据，再直接推进当前可执行任务，不停在规划或重新索要开始许可。单个低成本实验直接开展，不强制建立计划文件。

`iterate` 负责方向选择与证据驱动调整，`plan-skill` 负责具体任务和执行状态。复用已有计划，选择足够用的最轻模式，不因使用 iterate 自动升级为 Loop。先细化眼前可验证的任务，后续任务随证据展开；假设被否定时，更新或撤销依赖它的任务并保留原因，不为完成清单继续执行失效路线。任务状态和证据回写同一权威计划，不另建重复台账。

## 多 Agent：分开探索，统一验收

在运行环境允许且确有独立工作时，主 Agent 可委派互补的候选探索、竞争解释或反证检查。选择最小有用团队，不固定角色数量，也不为简单任务强行分工。

- 主 Agent 保留目标解释、共享预算、最佳已验证版本和最终决策的责任。拆给子 Agent 的是有界问题，不是无限递归任务。
- 规划、执行、审查是可合并的责任，不强制四角色流水线。委派只传相关约束、必要上下文和原始证据入口；验证者依据验收条件独立检查，不预设应当通过。保留失败与争议信息，不让执行者的成功叙述替代证据。
- 每项委派说明输入/起始版本、问题、可改范围、预算或停止条件、输出与验收证据。各分支预算合计不得突破总额；留出合并、验证和交接余量。未得到明确委派授权的子 Agent 不继续扩展团队。
- 独立候选使用独立产物目录、分支或副本；只读验证共享证据可以并行。不能隔离共享写入时串行处理，不让多个 Agent 同时改同一权威文件、评价器或记忆。
- 验证者检查真实状态、原始产物和约束，不只阅读执行者总结。多个 Agent 的同意不是独立证明，争议回到可核对的证据。
- 主 Agent 将候选整合后验证组合结果；子 Agent 分别通过不等于组合通过。只由一个负责者合并权威经验，保留冲突与未决内容，不按多数票写成事实。

## 验证、保留与记忆

把最佳已验证成果与当前尝试分开保存，沿用项目已有版本、差异、产物和日志机制，不默认复制整个仓库或另建状态系统。证据指向确切版本、输入与配置；依赖发生相关变化时重验受影响部分。失败候选只回退本次拥有的改动，不能覆盖用户或其他分支工作。

验收用实际运行和产物，而非执行者自评。不得削弱测试、删去失败样本或改变口径制造成功。评价器确有错误时，把它作为单独修复，记录原因并在修正协议下重测基线与候选；不能沿用不可比的旧成绩。

每轮在现有记录中简记：尝试、证据、结论、下一步。值得复用的经验保留适用环境/版本、动作与条件、观察结果、证据、反例或失效条件；区分待验证、已验证、过时。无需保存内部思考全文或把一次偶然成功固化为永久规则。

长任务额外保留当前有界问题、待交付产物和改变路线的依据；恢复时核对实际版本、产物及运行任务，不能只照旧计划重跑。沿用现有计划或状态文件，不另建一套 Campaign 系统。经验先留在证据支持的最窄范围；推广到领域或全局规则需要跨场景证据及相应写入授权，出现反证时撤销或收窄，而非不断叠加补丁。

要宣称经验提高了能力，冻结候选经验，在干净起点、未用于调整的案例上与适当基线比较，同时记录探索与执行成本。不能只重复原题；正式评测的隐藏答案不进入探索记忆。普通局部操作笔记不必全部接受能力基准测试。

## 预算与结束

关注已用和剩余的时间、工具/计算调用及并发成本，为最终验证和交接预留资源。不能准确计量费用或 token 时明确标注估计或未知，不编造数字，也不忽略可测的时间上限。停止时不再派发新实验；取消本次可安全取消的工作，其他运行任务记录标识、状态及恢复/停止方式。

收尾前对照真实停止条件与未决方向：目标尚未完成、预算仍允许且还有有价值的可执行实验，就继续做，不以“已有阶段成果”或“后续可以研究”替代执行。认为已无值得尝试的路线时，依据已做诊断和替代尝试说明，而非凭一次失败下结论；不编造新任务或无限无效试验。

- **目标完成**：明确验收条件已有证据满足，且授权内必做交付完成；不要继续为“还能更好”增加任务。
- **预算耗尽**：交付最佳已验证成果和剩余问题，不等于成功。无提升阈值但有预算的优化任务，在预算内寻找最好结果，不以任意小提升提前宣告完成。
- **用户中止**：停止新实验，保存状态并交接。
- **受阻**：经过有针对性的诊断和可行替代尝试，仍缺必要条件、用户决定或权限；说明阻塞及恢复条件，不机械重试。验证基础设施出错要明确报告错误，不能伪装成候选失败。

## 交接与衔接

最终交接包含适用内容：目标与结束原因、预算使用/估计边界、最佳已验证成果及版本和证据、未验证尝试、主要方向及结论、下一步与恢复方式、遗留运行任务。没有遗留项就省略，不强行添加后续工作。

本 Skill 负责推进方式，不替代领域判断。已有领域 Skill 继续定义正确性；例如数值样例不能代替数学证明，性能提升不能代替正确性验证。需要严谨研究比较时使用 [research-craft](../research-craft/SKILL.md)，任务规划按上文衔接 `plan-skill`。仅加载当前问题所需部分，复用目标、状态和证据，不默认串行跑多套流程。
