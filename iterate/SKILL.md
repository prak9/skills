# Iterate

自主选择路线，用证据学习，并交付最佳已验证成果。持续执行“核对证据—选择问题—实际试验—判断结果—更新下一步”；首个可用解和初始计划完成只是迭代节点。探索的价值在于改善成果、排除关键误判或打开更有价值的路线，不按轮数计功。流程可省略、合并或换序，保留事实、授权和验收边界。

## 起点与边界

复用已确认的目标、预算、评价标准、允许修改范围和必须保持的条件。简短说明目标、评价方式与第一步，检查相关代码、资料、历史尝试和运行状态，尽快获得真实反馈。用户要求继续时承接已有证据与未决方向；需要比较时建立可复现基线。

区分三种结束依据：明确目标按验收结束；预算内优化寻找更好的已验证结果；未设阈值与预算的开放优化，先用已有授权资源推进有价值的实验，再按有证据的搜索收敛或真实边界交付。小幅提升本身不是开放任务的完成条件，预算空缺也不是先做一轮就停的理由。

读取实际适用的领域 Skill，让它提供测量口径、工具和验证方法。瓶颈或问题类型变化时重新匹配方法；以得到什么测量、反例或验证结果判断是否有效使用，而非读取数量。只加载当前问题所需内容。

- 评价标准未指定时，从用户希望得到的结果建立可检查的标准；不要把宽泛优化请求改成自己编造的提升百分比或成功阈值。
- 范围内的常规可逆工作自行推进。先调查可查缺口；只有无法自行解决、且实质影响目标、授权或验收的用户决定才提问，同时完成不依赖答案的工作。
- 自主迭代不增加提交、推送、部署、实盘、外部写入或删除资源权限；也不授权修改评判自己的标准、权限控制或共享 Skill。

## 方向不清时，先人机共创

当目标含义、价值取舍或候选方向存在实质不确定性，且用户判断能明显改善方向选择时，主动邀请简短的 brainstorming。先利用已有资料，提供对问题的理解、区分事实与假设，并提出机制不同的候选方向及其价值、代价和关键未知；不要空手问“你想怎么做”，也不要把协作变成逐题审问。围绕真正影响选择的分歧交流，允许用户提出新方向，不要求固定数量的选项或逐段批准。

意图与取舍需要共同澄清；可查事实、技术可行性和瓶颈优先自行调查或实验，不让用户替 Agent 做技术诊断。讨论中可以穿插已授权的低成本探针，用结果帮助选择。尚待用户判断的关键取舍不擅自拍板，同时推进不依赖它的工作。

收敛到“知道接下来值得验证什么”即可，不必预先解决所有未知。简短保留共同明确的目标、方向、取舍、边界及待验证假设，沿用已有授权进入规划和执行；方向已明确则跳过，不把 brainstorming 变成通用审批关卡。

## 每轮选择最有价值的问题

围绕影响最终成果的关键瓶颈或未知选择行动。若有竞争方向，比较它们对成果的潜在影响、能排除的关键误判、实施与验证及整合的总成本，以及会打开哪些后续路线；无需数值打分、固定候选数量或逐项填表。已知瓶颈可以直接深入，方向不明时先找能区分解释的观察。

当分析或复盘只是在重复“再深入一点”“还不够好”等评价，且没有新的推导、可检验预期或证据时，把评价改成能区分关键解释的下一项观察，并实际获取反馈。聚焦当前主要未知，同时保留必要的事实、回归与权限检查；聚焦不等于只看一个指标，也不限制尚在形成问题的自由探索。复现和重复测量即使未改变结论，也可能降低不确定性，不能因“没有新结论”而省略。

行动前留下足以检验的预期：为何现在值得做、预期观察、验证方式、什么结果会改变选择。优先用便宜且有区分力的探针淘汰弱方向，再扩大投入。便宜不是唯一标准：总做边缘小实验会错过主瓶颈；测量或工具改进则要说明服务哪些后续实验、怎样节省成本，避免把优化任务变成平台建设。

持续研究时，把准备、执行、验证、返工和等待共同视为实验成本；用实际记录更新下一轮选择。先用局部探针辨别方向，再将有希望的候选送入可比验证与独立确认，检查小样本或短任务是否遗漏关键机制。成本下降后，为不同机制的探索、复现和评价器检查保留空间；所需分配随瓶颈调整，不固定比例。研究飞轮及记录接口按需使用 [research-craft 的参考](../research-craft/references/research-flywheel.md)，普通单次改动保持轻量。

在现有记录中保留仍有价值的方向、排除依据和重开条件。得到结果后更新选择，并实际推进下一项已授权实验；待办清单留有明确值得做的工作时，不能以“建议下一步”代替执行。反馈稀疏时，用中间产物或反例缩短反馈周期，并保留它与最终验收的区别。

等待尚未发生的外部结果时，说明等待对象、可观察的恢复条件和合理检查窗口；它不妨碍继续独立、已授权且有价值的工作。不要用“耐心”掩盖可执行的验证，也不要为保持忙碌重复无信息增量的检查或擅自创建后台监控。

动作会改变后续可见证据和可选路线。比较完整任务过程的交付、总成本及后续验证能力：修复测量或解除依赖可以暂时不提高分数，但要有可检查的用途和结果；不能只凭未来收益设想扩大建设。成功轨迹不证明其中每一步有效，按贡献证据保留方法。若选题、采样或执行策略变化，检查是否只是换了更容易的样本，并重验旧证据对新行为的适用范围；具体按 research-craft 的 [过程与采样检查](../research-craft/references/harness-engineering.md#evaluate-trajectories-and-policy-generated-data)。长期收益不抵消中间约束或授权边界。

根据证据选择或重排这些动作：

- **广探索**：检查机制不同的解释、工具路径或解法，建立足够完成目标的环境地图；无需遍历所有功能。
- **深验证**：瓶颈已知时，直接复现、测量、构造反例或测试边界；不强制先广后深，也不要求每轮更难。
- **小实验**：先做成本低、可隔离、可恢复的探针，再向有希望的候选投入。实验可以是代码、检索、测量、对照或消融。
- **换路线**：低收益时重查问题定义、测量有效性和瓶颈，再决定继续深挖或尝试不同机制。同机制的参数变化可以验证敏感性，但不能充当独立路线覆盖。

计算量成为瓶颈时，可以先问哪些工作能够省去，再考虑把原计算加速。允许重新表示问题、裁剪候选或共享状态；按 [performance 的结构性验证](../performance/references/structural-optimization.md) 检查原目标、约束与所需输出是否保留。经验上暂时无用的方向保留重开条件，不当作数学上永远无用；普通局部改动继续使用相称的验证。

结果解释决定下一步：实现出错先修实现；输入、仪器或对照失效先修实验；有效实验违背预测才支持收窄或否定假设。缺少区分力的结果保留未决，不能把它当反证。成功后重新看主要瓶颈、收益稳健性和剩余有价值的机制；失败后保留学到的限制，避免重复相同条件下的无效尝试。

允许大胆探索和多个因素一起变化来发现方向；若要把收益归因于某个因素，再用有区分力的对照验证。经验关系不自动成为因果规律。

探索陌生环境的写操作优先使用副本、测试账号或可恢复状态；不要把真实用户数据、生产系统当作试错场。已有授权不清楚是否覆盖某个副作用时，先做不产生该副作用的检查。

## 从方向到具体任务

选定方向后，若需要多个相互依赖的步骤、跨会话执行或多个 Agent 协作，使用 [plan-skill](../plan-skill/SKILL.md) 将方向转成具体任务，明确产物、依赖和验收证据，再直接推进当前可执行任务，不停在规划或重新索要开始许可。单个低成本实验直接开展，不强制建立计划文件。

`iterate` 负责选择下一问题、候选晋级与搜索结束，`plan-skill` 负责具体任务和执行状态。复用已有计划和最轻模式，不因使用 iterate 自动升级为 Loop。先细化眼前可验证的任务；证据改变路线时，更新或撤销依赖任务并保留原因。节点通过后回到原目标判断，计划完成不替代优化任务的结束依据。任务、未决方向和证据沿用同一权威记录。

## 多 Agent：分开探索，统一验收

在运行环境允许且确有独立工作时，主 Agent 可委派互补的候选探索、竞争解释或反证检查。优先分开不同机制或独立复现；若多个 Agent 只是重复相同建议，先重划问题而非增加人数。选择最小有用团队。

- 主 Agent 保留目标解释、共享预算、最佳已验证版本和最终决策的责任。拆给子 Agent 的是有界问题，不是无限递归任务。
- 规划、执行、审查是可合并的责任，不强制四角色流水线。委派只传相关约束、必要上下文和原始证据入口；验证者依据验收条件独立检查，不预设应当通过。保留失败与争议信息，不让执行者的成功叙述替代证据。
- 每项委派说明输入/起始版本、问题、可改范围、预算或停止条件、输出与验收证据。并发分支共用截止时间，累计计算与调用成本受总预算约束；留出合并、验证和交接余量。未得到明确委派授权的子 Agent 不继续扩展团队。
- 独立候选使用独立产物目录、分支或副本；只读验证共享证据可以并行。不能隔离共享写入时串行处理，不让多个 Agent 同时改同一权威文件、评价器或记忆。
- 验证者检查真实状态、原始产物和约束，不只阅读执行者总结。多个 Agent 的同意不是独立证明，争议回到可核对的证据。
- 主 Agent 将候选整合后验证组合结果；子 Agent 分别通过不等于组合通过。只由一个负责者合并权威经验，保留冲突与未决内容，不按多数票写成事实。

## 验证、保留与记忆

候选晋级分开判断：必须保持的条件是否通过；目标表现是否改善；比较证据是否足以替换当前最佳版本。沿用原目标、工作负载与取舍；多指标结果尚不可比时保留取舍，不临时挑选有利指标宣布胜出。证据不足的候选保持“有希望但未确认”，最终仍交付最佳已验证成果。

把完成度与优化分数分别验收，核对原范围内的必达项、允许延期项和未决项。跳过困难交付取得的高分不能抵消缺项，明确可选的工作也不阻塞完成。比较路线效率时使用同一任务与总预算，保留失败、返工和验证成本，结合多次结果的稳定性判断，单次速度或最好分数只作局部观察。

用领域适用的对照、重复测量或独立案例验证优势，不把单次最高分当稳定收益。噪声可能改变排名、反复选优可能过拟合、需要因果归因或评价器存疑时，使用 [research-craft](../research-craft/SKILL.md) 的相应方法；简单确定性检查保持轻量。额外复杂度与执行成本也要符合原有约束，收益相当时优先保留更简单稳健的方案。

把最佳已验证成果与当前尝试分开保存，沿用项目已有版本、差异、产物和日志机制，不默认复制整个仓库或另建状态系统。证据指向确切版本、输入与配置；依赖发生相关变化时重验受影响部分。失败候选只回退本次拥有的改动，不能覆盖用户或其他分支工作。

验收用实际运行和产物，而非执行者自评。不得削弱测试、删去失败样本或改变口径制造成功。评价器确有错误时，把它作为单独修复，记录原因并在修正协议下重测基线与候选；不能沿用不可比的旧成绩。

在现有记录中保留影响选择的尝试、证据、结论和下一步，遵循已有计划的记录约定。经验写明适用环境/版本、动作与条件、结果、证据及失效条件，区分待验证、已验证、过时。记录判断摘要，不保存内部思考全文。

复用已有 case/run/grade/finding/change 标识连接失败、干预和后续验证；经验真正改变了哪次选择，应能追溯。有效负结果也可排除路线，环境或评分故障则先修证据链。重复尝试记录总成本与样本暴露；已参与调优的验收案例转入开发或回归集合，后续晋级使用新的独立证据。

选择新路线、重试旧方案或恢复任务时，检索最相关的既有尝试，核对其依赖是否仍成立；证据怎样改变了当前行动，比记忆写了多少更重要。关键前提被否定或失效时，重评依赖结论及下一动作，不能只追加笔记后照旧执行；保留仍有独立支持的结论与无关已验证成果。同条件下的失败应约束下一次选择；输入、环境或实现条件已改变时可重开，并记录差异。去重和收窄过时经验，避免全量重读历史或把局部失败永久推广。

长任务额外保留当前有界问题、待交付产物和改变路线的依据；恢复时核对实际版本、产物及运行任务，不能只照旧计划重跑。沿用现有计划或状态文件，不另建一套 Campaign 系统。经验先留在证据支持的最窄范围；推广到领域或全局规则需要跨场景证据及相应写入授权，出现反证时撤销或收窄，而非不断叠加补丁。

要宣称经验提高了能力，冻结候选经验，在干净起点、未用于调整的案例上与适当基线比较，同时记录探索与执行成本。不能只重复原题；正式评测的隐藏答案不进入探索记忆。普通局部操作笔记不必全部接受能力基准测试。

## 阻塞先自解，不能解决就明确抛出

遇到失败先判断卡住的是某条方法、验证条件还是整个目标，不把一次工具报错、缺少输入或候选失败直接当成任务受阻。根据错误与实际状态定位原因，在授权和预算内主动修复可恢复问题，或尝试能达到同一验收目的的替代工具、数据来源、隔离复现或执行顺序；选择有依据的尝试，不要求凑次数，也不重复无信息增量的重试。替代路径不能靠降低验收、编造缺失数据或扩大权限来“打通”。

局部受阻时继续不依赖它的有效工作，保留最佳已验证成果。经过针对性诊断和合理替代仍不能解除，或已确认缺少只能由用户/外部提供的必要条件时，及时明确抛出：卡在哪里、影响哪些交付、已尝试什么及证据、还缺什么、谁能提供，以及恢复所需的最小动作。不要把阻塞藏在“后续建议”里，也不要因已有部分成果宣称整体完成。已确认的权限或用户决定边界无需靠反复试错证明；只暂停受影响部分，需要用户介入时明确提出请求。

## 预算与结束

关注已用和剩余的时间、工具/计算调用及并发成本，为最终验证和交接预留资源。不能准确计量费用或 token 时明确标注估计或未知，不编造数字，也不忽略可测的时间上限。停止时不再派发新实验；取消本次可安全取消的工作，其他运行任务记录标识、状态及恢复/停止方式。

收尾前核对原目标、剩余资源和未决方向。条件允许且仍有价值明确的可执行实验，就执行它；一次失败、固定无进展轮数或首轮提升均不单独构成结束依据。按实际情况区分：

- **目标完成**：明确验收条件已有证据满足，且授权内必做交付完成；不要继续为“还能更好”增加任务。
- **预算耗尽**：交付最佳已验证成果和剩余问题，不等于成功。无提升阈值但有预算的优化任务，在预算内寻找最好结果，不以任意小提升提前宣告完成。
- **本次搜索收敛**：用于开放优化。主要瓶颈和有希望的替代机制已有检查依据，剩余可执行实验在当前范围与成本下难以改变选择。说明检查过什么、排除了什么、仍未知什么，以及何种新证据值得重开；交付本次范围内最佳结果，不宣称全局最优。明确验收尚未满足时，这只能说明搜索现状，仍须如实报告未达标。
- **用户中止**：停止新实验，保存状态并交接。
- **受阻**：按上述阻塞处理仍缺必要条件、用户决定或权限，且没有可继续的有效工作；交付证据与具体恢复请求，不机械重试。验证基础设施出错要与候选失败区分，不能伪装成验收通过。

## 交接与衔接
