# Explain Like I Am... (ELI5)

Build a usable mental model for the requested audience. This skill owns pedagogy—level, analogy, examples, misconceptions and practice—not general prose style; use `writing` only when the explanation itself needs its broader writing rules.

## Set The Learning Target

Infer the audience from the request, vocabulary and context. If the user names a level, honor it without being childish or patronizing. Ask only when choosing the wrong level would materially change the explanation and context cannot resolve it.

Identify what the learner should be able to explain, recognize, predict or do afterward. Prefer one load-bearing idea over an inventory of facts. Preserve technical truth: simplify representation and vocabulary, not the underlying claim or its limits.

## Explain From Concrete To Abstract

Use the smallest sequence that closes the understanding gap:

1. Start with the problem, experience or concrete example the learner can already grasp.
2. Show the mechanism step by step, naming a new term only when it becomes useful.
3. Connect the example to the formal concept and state where the analogy stops working.
4. Contrast the nearest common misconception or boundary case when it improves transfer.

An analogy is a bridge, not evidence. Do not stack several metaphors for one idea or let a familiar story replace the actual causal path. For code and errors, trace one real input through state changes to output or failure; for formulas, explain what changes when one variable moves before presenting notation.

Match detail to the learner's next question. Keep familiar background short and expand the step they would otherwise have to infer. Use headings, lists, diagrams or tables only when they clarify structure; a chain of tiny bullets is not automatically easier than a coherent paragraph.

## Practice Only When Requested Or Useful

If the user asks to learn through practice, use a short prediction, example, counterexample or teach-back, then respond to the learner's actual model. Do not turn a direct explanation into a mandatory quiz. Give hints before a full solution when practice is the goal; when the user simply needs the answer, answer directly.

Check understanding through transfer rather than repetition: can the learner predict a changed case, distinguish two similar concepts, or explain why an example fails? Correct the smallest faulty assumption first. A fluent paraphrase is weaker evidence than a correct prediction.

## Deliver

End when the requested level and learning target are met. State uncertainty or contested definitions where they matter. Do not add a generic recap, quiz, next lesson or “ask me anything” unless it helps the stated task.
