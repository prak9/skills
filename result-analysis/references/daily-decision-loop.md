# 日报图片与运行建议

仅当用户请求日报图片、完整日报交付或下一交易时段运行建议时使用。研究方向本身不触发本参考。图片、运行建议和研究交接是独立交付项，按请求选择；以下模块不是必须顺序执行的清单。

## 数据与比较范围

需要字段/身份解释时读 [数据与指标](analysis-contract.md)，不要仅因进入日报任务重新读取已确认的口径。新报告以最新完整一日 bundle 为 D0；涉及变化或稳定性时选相关的同身份历史，默认查找窗口及运行门槛见 [py 项目政策](project-policy.md)。只做当日展示不强制补历史。

图表/比较标明日期、账户、品种与 session、样本量、缺失和 SIM/REAL/回放。身份变化按最小受影响单元拆 cohort，不用跨身份均值掩盖变化；数据不足时保留可复算的事实，限制相关结论，不阻断其它独立问题。

只有运行建议才恢复盘前批准的配置或运行卡，区分：

| 角色 | 来源与边界 |
|---|---|
| `PREAPPROVED_LIVE` | 盘前有效运行卡/配置；当前被批准的集合 |
| `REAL_OBSERVED` | 当日订单与成交；不能反推批准范围 |
| `POSTHOC_CANDIDATE` | `meta.recommend` 或盘后排名；不能改写为盘前推荐 |

缺实盘批准记录时仍可总结当日结果，但不能伪造运行状态或新增实盘资格。日报不能凭单日 SIM 盈利新增实盘品种、切换模型、提高仓位或写 `PROMOTE`；具体状态与资格沿用项目政策。

## 图片模块：仅生成需要的部分

用户只要一张图或某个品种时就交付该范围；只有明确请求完整日报图包时才采用完整模板。先得到可复算的数据，再渲染。图表标题写所回答的问题或有证据支持的结论，不为标题强造决策。

| 可选模块 | 用途 |
|---|---|
| 决策/结果首页 | 关键结果、可比范围、最重要变化和实质不确定性 |
| 品种 × session 矩阵 | 请求全局比较时列 SIM 与 REAL、样本、身份和缺失 |
| 逐品种卡 | 用户关心的品种或需解释的异常；完整实盘复盘覆盖已批准集合及当日活动，保留未入选范围与理由 |
| SIM 会计桥 / REAL 结果卡 | 请求收益拆解时使用下述口径，不画伪因果瀑布 |
| 研究卡 | 用户要求研究方向时才加：机制、竞争解释、最小辨别证据 |

卡片可从跨日经济性、预测到交易、尾部、实际执行中选择与问题有关的内容，不强制六区域或给每个品种造下一步。若在完整模板中比较/推荐候选，不隐藏未入选 universe；附表可承载明细。

### 收益与传导图的口径

- SIM 会计桥：同口径 `gross - modeled fee/rebate drag = net`，注明账户、日期、cell 范围。缺 latency、queue、markout 等证据时写不可观测，不从残差倒推。
- REAL：先单列实际结果桥，再在确有对应数据时展示 matched-cell aggregate proxy；标明配对范围、unmatched 和 ordered/filled/unfilled 的聚合边界。
- 未逐决策配对的 `execution/selection residual` 保持 `UNRESOLVED`，不得重命名为滑点、延迟、漏单或逆向选择。
- SIM 与 REAL 可并列展示，但不是一条闭合因果瀑布。不同 universe/单位不能共用柱长作贡献比较；没有 REAL 数据时标 `NO_LIVE_DATA`，不画零值。
- 真实成交价已反映的 spread/impact 不重复扣除。实际字段以报告 `meta.note` 与生成代码为准。

图中保留来源、聚合、单位、样本与影响解读的缺口；无需固定标签串。不要以双轴、截断轴或未经校准的颜色概率制造效果。只用颜色区分不够，SIM/REAL/回放及缺失同时有文字标识。篇幅不足时精简背景或拆页，不隐去重要边界。

## 运行建议：只有请求时生成

日报是盘后分析，不代替已经验证的实时策略。给出运行建议时说明对象、现行状态、证据、有效期和改变判断的触发器。使用项目已定义的状态，不能从建议推断操作授权：

| 状态 | 含义 |
|---|---|
| `KEEP_CURRENT` | 保持已批准配置与限额；不表示再次确认 edge |
| `WATCH` | 异常/改善待确认，证据不足 |
| `DIAGNOSE` | 优先调查相应问题，不据此扩量 |
| `SHADOW_ONLY` | 只作 SIM/影子候选，不进入实盘 |
| `RISK_REVIEW` | 既有数据、会计、风险或运行故障触发器命中后的复核 |
| `WEEKLY_REVIEW` | 满足条件后提交周审，不改变部署 |

新增实盘、扩量和切模服从 [项目政策](project-policy.md) 及适用的 fixed evaluator、容量、风险和人工批准。单日亏损不够发明新暂停阈值；原因未明也不能延后既有已批准风险处置。具体手数仅在用户要求且证据充分时讨论，不直接执行。

## 研究方向：不强制闭环

以相关事实提出机制、最强竞争解释和最便宜的辨别检查；无需补全候选参数、split 或整张实验表才能提出问题。只有形成正式比较实验提案时才固定 editable surface、评估数据、指标和停止条件。

测量、部署、策略、模型、容量是诊断视角，不是逐级通关顺序。每个结论先保护其依赖的证据；没有配对不能用重训解释 REAL−SIM，但独立已复现的标签错误可以立即提出修复与重建基线，不等无关问题闭合。多个有依据的问题可分别排序，不强行唯一瓶颈。

日报建议若改变 universe、gate、size 等政策，后续数据属于新的 policy-conditional cohort，不能混入旧数据自证有效。evaluator 或测量本身变更时，先校验并重建可比基线，再比较策略。

只在需要向执行方交接时形成 research handoff，说明问题、证据、待验证结果和权限边界，不自动落盘。普通日报回答完成即可结束；持续跟踪、写日志与推送沿用明确授权。
